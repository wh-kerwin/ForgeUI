# ADR 0002：保留业务 PageSpec，分离页面定义与运行数据

- 日期：2026-10-22
- 状态：Proposed（实施前设计决策，尚非已完成状态）
- 依据：[json-render 源码研究](../research/json-render-design-study-2026-10-22.md)

## 背景

产品面向 B 端 API 工作台。当前 PageSpec 同时保存页面与真实 rows，查询会覆盖 columns；TS/Rust/提示/Schema 存在漂移。项目已有 React/Ant Design 业务组件、Tauri 网络授权、多 API 文档与版本模板。目标不是建设通用跨端 UI 框架。

## 决策

1. 不引入 json-render runtime，不迁移到 root/elements 图；保留有限业务 DSL。
2. 用小型能力目录统一可用场景、视图和动作的描述，引用版本化权威契约。
3. 引入 PageDefinition v2 与内存 PageRuntimeState，raw 数据/身份不进入页面定义。
4. JSON Schema 是 v2 字段约束来源；TS 生成，Rust 验证原始 JSON并保留领域校验，通过共享 fixtures 守住一致性。
5. Rust 继续控制网络、凭证和最终授权；只允许固定宿主动作，禁止任意模型代码。
6. 保留当前 SSE/JSON 协议，先修调度与取消；v1 通过显式迁移兼容，不直接重写旧数据库。

## 备选与后果

| 方案                 | 优点                        | 放弃原因或代价                                   |
| -------------------- | --------------------------- | ------------------------------------------------ |
| 完整引入 json-render | 通用组合与生态丰富          | 不能解决业务语义，新增双 DSL、图校验和迁移成本   |
| 只增强 Prompt        | 成本低、变化小              | 不能解决空结果、身份、取消、数据持久化与契约漂移 |
| 本决策               | 复用现有投资，边界适合 B 端 | v2 需跨前后端/持久化同步实施，必须分阶段门禁     |

失败策略：候选定义不通过则保留上一有效页；绑定不确定仅预览；迁移保留旧版本与报告；写请求结果不明要求核对。退出条件与详细测试见[实施计划](../plans/2026-10-22-b2b-generative-ui-implementation.md)。

如未来产品确实需要用户任意搭配大量组件、多端 renderer，或受控局部 patch 的收益经评测超过协议复杂度，再新增 ADR 评估图 DSL，不在本轮预埋插件体系。
