# Forge UI B 端业务工作台 PRD（实现状态）

> 本文是 2026-11-12 的 B 端范围与**真实实现状态**。2026-10-22 前的 C 端定位已废弃，不再作为新功能依据；历史结论保留在 git 历史与 [旧优化报告](optimization/b2c-page-generation-optimization.md) 中。当前进度见 [B 端执行记录](optimization/b2b-execution-log.md)，回归与验证结论见 [B 端验收报告](optimization/b2b-acceptance-report.md)，任务口径见 [实施计划](plans/2026-10-22-b2b-generative-ui-implementation.md)。

## 1. 产品定位

Forge UI 是本地优先的**生成式业务 UI 桌面客户端**：连接已存在的 OpenAPI/Swagger 服务，用一句自然语言生成受控的查询、看板与 CRUD 页面，由本地客户端执行校验、授权、数据映射、请求与渲染。

模型只产出 `PageSpec` 页面描述，不产出可执行的 HTML/CSS/JavaScript；所有写操作必须由用户明确提交，删除需确认。它不是低代码编辑器，也不是让模型任意生成网页代码的构建器。

## 2. 目标用户与场景

- 需要快速查看内部系统数据的开发者、业务分析师和内部工具维护者。
- 面对多个后台服务、不想为每个接口重复编写固定前端的团队。
- 需要临时生成报表/资源管理页，并保存为可复用模板再按项目重绑定的使用者。

典型任务：连接并授权 API 文档 → 描述需求生成页面 → 查询/筛选/排序/详情/CRUD → 对话式局部修改 → 保存模板 → 在另一个项目导入并显式重绑定 → 恢复历史版本。

## 3. 范围边界

**在范围内**：受控 `PageSpec` v1 生成与保存；OpenAPI 摘要与授权 operation；显式 RFC6901 响应映射；定义/运行时分离；typed 记录身份；筛选、当前页与服务端统计作用域；模板与生成历史；结构 allowlist 投影与持久化再验证。

**不在范围内**：联邦查询/join、任意 GET 冒充全库统计、模型返回的任意代码执行、自动恢复失效授权、缓存/自动轮询/多源联动复杂图（留待下一 ADR）、v2 默认写入与 v2 runtime 执行。

## 5. 安全与数据完整性边界

- 模型、模板、会话与诊断只接收结构 allowlist 投影；已加载 rows、字面统计、自定义载荷与凭证不外发、不进入模板或历史。
- 模板/会话保存与恢复在 Rust 侧再次净化并校验授权范围；跨项目文档 ID 不沿用。
- 记录身份按原始类型区分（`string:001` ≠ `number:1`）；缺失或重复 ID 禁用该行写入与批量操作。
- 查询失败保留旧数据但明确标记过期并禁写；取消/切项目的迟到响应不提交。
- 统计：当前页聚合明确标注范围，服务端聚合必须绑定真实统计端点，缺绑定显示未绑定，局部失败保留错误区域。

## 6. 未实现 / 延后 / 已知风险

- 默认 v2 写入仍关闭：v2 runtime 与写入入口未接入，按「写入版本不能先行」保持。
- 统计端点的实际 HTTP 拉取未接入宿主；未注入响应时指标显示「等待执行」，不伪装数值。
- 真实模型 live 评测**未运行**；不在自动测试中消费 token。
- 本地桌面端到端 smoke **未运行**；本轮不能给出「项目可安装运行」的结论。
- 缓存、自动轮询、多源联动复杂图留待下一 ADR；E1 统计与报表语义中的复杂图未实现。
- 全仓 `format:check` 仍有大量既有未格式化 fixtures；本轮按约定只格式化自己改动的文件，见 [验收报告](optimization/b2b-acceptance-report.md)。

## 7. 验收方式

- 阶段门禁：`npm test`、`npm run test:ui`、`npm run contract:check`、`npm run lint`、`npm run build`、`cargo fmt --check`、`cargo test --lib`、`cargo check --features updater`，以及定向 Prettier/`git diff --check`。
- 离线评测：`npm run evaluate`，固定输入与结构化预期行为，覆盖 contract/binding/execution 三层，不检查提示词是否包含关键词。
- live 评测需显式 `--live` 与 `FORGE_UI_LIVE_EVAL=1`，由用户自行授权；报告须分别记录首轮合法定义率、绑定正确率、操作可执行率、重试率、fallback 率与延迟，repair/retry/fallback 单列，fallback 不计入模型首轮正确。
- 桌面 smoke 只在隔离 mock 服务上写数据，未实际执行前不得写成已验证。
